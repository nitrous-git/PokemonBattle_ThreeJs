# Implementation decisions

The supplied eight design documents are preserved in this directory as the v2 baseline. This note records concrete implementation choices and modest scope differences.

1. The five major conditions are burn, paralysis, sleep, freeze and poison; confusion is volatile. The contradictory “six major statuses” wording is treated as a count typo.
2. Domain uses immutable input snapshots and returns a cloned next state plus frozen semantic events. AI gets the public state before player commands resolve; it does not receive the player's pending slot. Decorative randomness is independent.
3. Crits ignore negative attacking stages and positive defending stages. Burn still halves physical attack. PP is deducted before status blocking, per the requested simplified design.
4. Accuracy/evasion use the standard 3-based stage multiplier; ordinary combat stats use the specified 2-based multiplier. Swift and declared self/status always-hit moves are explicit, not inferred from nullable source metadata.
5. End-of-turn burn/poison applies to living actors in player-then-opponent order, then final KO/draw checks. Struggle recoil can cause a draw. There is no hidden turn cap; after PP depletion, Struggle guarantees progress.
6. Hard AI is **sampled two-turn minimax**, not exact expectimax. It evaluates at most 272 transitions using common deterministic stochastic samples; terminal results dominate HP/status/stage utility. A small utility tie-break avoids purposeless choices.
7. Source: official PokéAPI api-data mirror, pinned Git commit. Direct API endpoint was blocked during implementation. The included optional importer supports both. All 95 resources (16 species, 61 moves, 18 types) were fetched and identity-checked. No invented fallback stats.
8. Raw source, curated rules and compiled catalogue remain separate. The authored move table deliberately changes Growth to Grass and Charge to a SpA boost, among other simplified effects. Changes are reported in overrideAudit.json. Twenty-one source-unobserved species/move combinations are retained as explicit supplied-design exceptions.
9. Real sprites are packaged in a **private educational profile**, with restricted rights flags. All 32 front/back sources were animated and successfully converted. Public-source packaging substitutes original geometric stand-ins and removes private screenshots/dist. No fonts, music rips or Java assets were copied.
10. UI uses local system fonts rather than downloading Pixelify Sans. This keeps the package compact and offline. The canvas uses simple lit procedural geometry and unlit pixel sprites, with no postprocessing blur/bloom.
11. Several tiny proposed files are consolidated: rules/stat/type/drafting helpers in `rules.js`; battle factory/turn resolver/results in `battle.js`; progression transactions in `progression.js`; arena/sprite/VFX lifecycle in `ArenaScene.js`; screens in `GameApp.js`. UI component templates remain separate. Prettier formatting and JSDoc make the compact layout approachable in WebStorm.
12. Save export is included. Import UI is deferred; no overworld, evolving roster, party switches, abilities or held items. Battle snapshots are intentionally not persisted. Cross-tab stale revisions are rejected. Unknown catalogue IDs preserve raw saves and trigger recovery, not random replacement.
13. Every damaging move has type-colored visual feedback. Effect families include sparks/bolts, rings, embers, leaves and crystal/rock shards, with physical lunges and status halos. These are reusable stylized treatments rather than 61 bespoke attack cinematics.
14. Production screenshots and automated tests demonstrate correctness in Chromium on Linux. A 55+ FPS claim for a Windows GPU is deliberately not made without a hardware run.
